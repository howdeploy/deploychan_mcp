# Система памяти и эволюция

Агент каждый раз читает заметки заново — вопрос в том, **в какой форме ему подаются
знания**. От этого зависит, помнит он всё за секунды или тонет в ОЗУ. Ниже — лестница
от простого к сложному. Правильный ответ — не «самое крутое», а «подходящее под человека».

**Что должен сделать агент:** расспросить человека (приватность? дешёвый VPS? огромные
доки? нужна эволюция?), подобрать стек с этой лестницы и настроить. Не тащить вектор
туда, где хватит вики.

## Лестница памяти

**1. LLM Wiki — заметки в .md.** Агент пишет заметки в markdown, читает через Obsidian,
а в системных инструкциях знает, куда сходить. Правила ведения вики лежат в самой вики и
в скиллах (пример — ObsidianDataWeave; связки строит graphify). Стиль записей «по
Карпаты». Просто, прозрачно, без ресурсов. Минус: не годится для быстрого поиска по
огромному массиву и точного цитирования.

**2. FTS5 — SQL по ключевым словам.** Те же заметки, но в базе с полнотекстовым индексом
(FTS5). Семантику не ищет, но за секунды достаёт по ключевым словам целые чаты за месяцы.
Именно поэтому Hermes «всегда всё помнит». Покрывает 90% случаев, дёшево, без ресурсов.
Кстати, сам этот MCP-сервер стоит ровно на SQLite+FTS5.

**3. RAG / RLM — вектор и семантика.** Векторные БД: заливаешь целые книги, агент ищет
по смыслу — глубоко и логично. Минус: постоянно держит ОЗУ (2 толстые книги ≈ 3 ГБ), для
дешёвого VPS это смерть. Классический RAG статичен. **RLM** делает векторную БД
динамичной — агент всегда обновляет данные на актуальные и ничего не забывает. Бери, если
нужно зафиксировать знания на 99.9% и ссылаться на книги/доки/политику — и ты готов
повайбкодить своё решение из готовых фреймворков.

**4. Holographic — HRR, локально, без зависимостей.** Memory-провайдер Hermes на основе
Holographic Reduced Representations: алгебраическая память поверх локального SQLite,
trust-scoring, мгновенный recall и **ноль внешних вызовов** (ни LLM, ни эмбеддингов, ни
сети). Идеален для приватности, air-gapped и слабого железа. Минус: качество поиска ниже
эмбеддингов, нет синтеза памяти. Ставится `hermes memory setup` → holographic.

**5. Curator — курация встроенной памяти.** Не свалка, а курируемая память: агент делает
выжимки полезного (факты о человеке, проектах), ведёт session-search и самоулучшается,
решая что достойно сохранения. Без курации семантическая память превращается в помойку.
У Hermes это встроенный слой (MEMORY.md / USER.md); аналог — `reflect` у Hindsight
(периодический синтез поверх всех воспоминаний, лучший бенчмарк LongMemEval).

**6. GEPA — эволюция промптов (опционально).** GEPA (Genetic-Pareto, Berkeley,
arXiv 2507.19457) — агент читает свои трейсы (рассуждения, вызовы тулзов, ошибки),
рефлексирует на естественном языке, диагностит провалы и **эволюционирует собственные
инструкции**, держа Парето-фронт лучших вариантов. Обгоняет RL при кратно меньшем числе
прогонов. Это и есть «эволюция»: агент со временем переписывает себя под задачи.

## Хуки против галлюцинаций

Отдельная недооценённая история — **система хуков**: заскриптованные события агента.
Хуком можно на старте сессии подтягивать якорь из LLM Wiki, а после ответа — проверять
факты. Это дешёвый и мощный костыль против галлюцинаций и полигон для экспериментов.

## Как выбрать под человека

- Прозрачно и дёшево, всё под контролем → **LLM Wiki**.
- Дефолт, 90% задач, память «из коробки» → **FTS5** (Hermes / этот MCP).
- Точное цитирование огромных доков, есть ОЗУ → **RAG / RLM**.
- Приватность, слабое железо, ноль зависимостей → **Holographic**.
- Память должна сама себя чистить и улучшаться → **Curator / Hindsight reflect**.
- Агент должен эволюционировать сам → **GEPA**.

Экосистема Hermes даёт 8 провайдеров (Honcho, OpenViking, Mem0, Hindsight, Holographic,
RetainDB, ByteRover, Supermemory) — переключение одной командой `hermes memory setup`.
Для Claude Code / Codex базу (Wiki + хуки) агент собирает сам, тяжёлое (RAG/RLM) —
вайбкодит. Смысл один: собрать под человека личную систему, в которой агент не забывает
и растёт.
