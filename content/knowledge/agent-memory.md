# Система памяти и эволюция

Агент каждый раз читает заметки заново — вопрос в том, **в какой форме ему подаются
знания**. От этого зависит, помнит он всё за секунды или тонет в ОЗУ. Ниже — лестница
от простого к сложному. Правильный ответ — не «самое крутое», а «подходящее под человека».

**Сначала ресерч, потом выбор.** Память — последний шаг маршрута не случайно: инструменты
памяти (провайдеры, фреймворки, бенчмарки) меняются быстро. Прежде чем выбирать, включи
выход в интернет (шаг 1, «Интернет и ресерч») и сверь текущее состояние вариантов
live-поиском — не полагайся на память модели, она устаревает. Стек выбирается на реальных
данных.

**Что должен сделать агент:** расспросить человека (приватность? дешёвый VPS? огромные
доки? нужна эволюция?), подобрать стек с этой лестницы под свой рантайм и настроить. Не
тащить вектор туда, где хватит вики.

## Лестница памяти

**1. LLM Wiki — заметки в .md.** Агент пишет заметки в markdown, читает через Obsidian,
а в системных инструкциях знает, куда сходить. Правила ведения вики лежат в самой вики и
в скиллах (пример — ObsidianDataWeave; связки строит graphify). Стиль записей «по
Карпаты». Просто, прозрачно, без ресурсов. Работает у любого клиента. Минус: не годится
для быстрого поиска по огромному массиву и точного цитирования.

**2. FTS5 — SQL по ключевым словам.** Те же заметки, но в базе с полнотекстовым индексом
(FTS5). Семантику не ищет, но за секунды достаёт по ключевым словам целые чаты за месяцы.
Именно поэтому Hermes «всегда всё помнит». Покрывает 90% случаев, дёшево, без ресурсов.
Кстати, сам этот MCP-сервер стоит ровно на SQLite+FTS5.

**3. RAG — вектор и семантика.** Заметки, книги и доки режутся на куски, каждый кусок
превращается в эмбеддинг (вектор смысла) и ложится в векторную БД. Агент ищет не по
словам, а по значению — «похоже по смыслу». Заливаешь целые книги/доки/политику — агент
цитирует их глубоко и логично. Это отдельная ступень со своими развилками:

- **Статичный RAG** (классика, Lewis et al., 2020). Проиндексировал корпус один раз —
  дальше только читаешь. Данные поменялись → индекс устарел. Наивно переиндексировать всё
  заново дорого; правильно — **инкрементально**: `upsert` только изменённых кусков (вставь
  новый / обнови существующий), delta-индекс поверх стабильного. Это и есть «держать
  память актуальной» на уровне вектора.
- **Динамический / agentic RAG.** Агент сам решает, что дозабрать, переформулирует запрос,
  дописывает и обновляет собственную базу на ходу — знания не застывают. Дороже по latency,
  но не врёт устаревшим.
- **Цена — не векторы, а модель в RAM.** Сами эмбеддинги дешёвые: вектор = `dims × 4` байта
  (1536-dim → ~6 КБ). Пара толстых книг — это несколько тысяч кусков, ~10–150 МБ, НЕ
  гигабайты. ГБ-масштаб начинается на сотнях тысяч векторов (~6 ГБ на 1 млн @1536d) — это
  библиотека в сотни книг. На дешёвом VPS RAM жрут не вектора пары книг, а **резидентная
  модель-эмбеддер** (сотни МБ–ГБ), опциональная локальная LLM и **in-memory движки**
  (Redis/FAISS в RAM). Лечится диском: `pgvector` (поверх Postgres), `Chroma`, `Qdrant`,
  `sqlite-vec` держат вектор на диске. Оркестрация ретрива — `LangChain` / `LlamaIndex`.

> Не путать с **RLM (Recursive Language Models**, MIT CSAIL, Zhang 2025). Это НЕ хранилище и
> не вид RAG, а техника инференса против *context rot*: длинный контекст (10M+ токенов) кладут
> в переменную Python-REPL, модель пишет код чтобы его резать/грепать и рекурсивно звать
> под-LLM. Место RLM — рядом с harness и компактом, а не в лестнице памяти (разбор — знание `rlm`).

Бери вектор, когда надо зафиксировать знания на 99.9% и ссылаться на большие
доки/книги/политику, есть ресурсы под ОЗУ/диск, и ты готов повайбкодить решение из готовых
фреймворков. Не тащи его туда, где хватит FTS5 по ключевым словам.

**4. Holographic — HRR, локально, без зависимостей.** Memory-провайдер Hermes на основе
Holographic Reduced Representations: алгебраическая память поверх локального SQLite,
trust-scoring, мгновенный recall и **ноль внешних вызовов** (ни LLM, ни эмбеддингов, ни
сети). Идеален для приватности, air-gapped и слабого железа. Минус: качество поиска ниже
эмбеддингов, нет синтеза памяти. У Hermes ставится `hermes memory setup` → holographic;
на других клиентах эквивалент вайбкодится.

**5. Curator — курация встроенной памяти.** Не свалка, а курируемая память: агент делает
выжимки полезного (факты о человеке, проектах), ведёт session-search и самоулучшается,
решая что достойно сохранения. Без курации семантическая память превращается в помойку.
У Hermes это встроенный слой (MEMORY.md / USER.md); аналог — `reflect` у Hindsight
(периодический синтез поверх всех воспоминаний, лучший бенчмарк LongMemEval).

**6. GEPA — эволюция промптов (опционально).** GEPA (Genetic-Pareto, Berkeley,
arXiv 2507.19457) — агент читает свои трейсы (рассуждения, вызовы тулзов, ошибки),
рефлексирует на естественном языке, диагностит провалы и **эволюционирует собственные
инструкции**, держа Парето-фронт лучших вариантов. Обгоняет RL при кратно меньшем числе
прогонов. Это и есть «эволюция»: агент со временем переписывает себя под задачи. Не
провайдер Hermes, а публичный пакет — ставится где угодно (см. ниже).

## Кто как ставит (по клиентам)

Половина лестницы — это удобства конкретного клиента, а не универсальные пакеты. Развилка
зависит от того, кто ты (шаг 0: определи рантайм).

**Hermes — из коробки.** Менеджер памяти встроен: `hermes memory setup` переключает между
8 провайдерами (Honcho, OpenViking, Mem0, Hindsight, Holographic, RetainDB, ByteRover,
Supermemory). Curator, session-search, HRR-память Holographic — всё готовое, одной
командой. Человек на Hermes — это самый короткий путь.

**Claude Code / Codex — собирают базу сами.** Встроенного менеджера памяти нет, стек
складывается руками — но это несложно:

1. **LLM Wiki** — работает сразу, ставить нечего. Markdown + правило «куда ходить» в
   инструкциях. База для всех.
2. **FTS5** — вайбкодится: SQLite + полнотекстовый индекс над заметками/логами + команда
   поиска. Ровно то, на чём стоит этот MCP. День работы, покрывает 90%.
3. **Хуки** — у Claude Code система хуков из коробки (якорь на старте сессии, факт-чек
   после ответа). У Codex персистентных хуков нет — тот же эффект даёт скрипт-обёртка
   вокруг вызова.
4. **Тяжёлое (RAG-вектор, HRR уровня Holographic)** — вайбкодится по потребности из готовых
   фреймворков. Не «из коробки», но подъёмно.

**А GEPA, если клиент не Hermes?** GEPA — не провайдер Hermes, а публичный Python-пакет:
`pip install gepa`, либо `dspy.GEPA`, либо `mlflow.genai.optimize_prompts()`. Поставить
может любой агент. Нюанс не в установке, а в том, что это не «память из коробки»: GEPA
эволюционирует твои промпты/инструкции под eval-сигнал (задача + метрика), который надо
задать. Для Claude Code / Codex это вайбкод-проект: собрать метрику, скормить свои трейсы,
получить улучшенные инструкции. Лёгкая версия того же принципа, без пакета — руками:
периодически читай свои трейсы, рефлексируй и переписывай собственные `CLAUDE.md` /
`AGENTS.md` / слэш-команды, оставляя лучшие версии. Это и есть «эволюция» для не-Hermes
клиента.

## Хуки против галлюцинаций

Отдельная недооценённая история — **система хуков**: заскриптованные события агента.
Хуком можно на старте сессии подтягивать якорь из LLM Wiki, а после ответа — проверять
факты. Это дешёвый и мощный костыль против галлюцинаций и полигон для экспериментов.
У Claude Code хуки из коробки; где их нет — оборачивай сессию скриптом.

## Как выбрать под человека

- Прозрачно и дёшево, всё под контролем → **LLM Wiki**.
- Дефолт, 90% задач, память «из коробки» → **FTS5** (Hermes / этот MCP).
- Точное цитирование огромных доков, есть ресурсы → **RAG** (вектор).
- Приватность, слабое железо, ноль зависимостей → **Holographic** (Hermes) или вайбкод-аналог.
- Память должна сама себя чистить и улучшаться → **Curator / Hindsight reflect**.
- Агент должен эволюционировать сам → **GEPA** (`pip install gepa` / `dspy.GEPA`).

Смысл один для всех клиентов: собрать под человека личную систему, в которой агент не
забывает и со временем растёт. Hermes даёт её командой, Claude Code и Codex — руками.
Ступень выбирается под человека и под реальные данные, а не по хайпу.
