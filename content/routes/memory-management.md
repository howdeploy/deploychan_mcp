# Прокачка памяти: что где хранить

Агент каждый раз читает знания заново — вопрос в том, ЧТО он помнит, ГДЕ это лежит и НАСКОЛЬКО
оно свежее. Плохая память хуже отсутствия: устаревший факт агент выдаёт за правду. Этот
маршрут — про управление актуальными данными: какой ТИП данных ложится в какой ВИД памяти, и
что вообще не надо запоминать.

**Шаг 0 — пойми, кто ты.** Как ставится память, зависит от рантайма: Hermes даёт стек командой
(`hermes memory setup`), Claude Code и Codex собирают руками. Определи клиент через
`tailored-install`. Полная лестница памяти и развилка по клиентам — в знании `agent-memory`.

## Три оси: данные → хранилище → свежесть

Свежесть решает ПЕРВОЙ. Живое (курсы, версии либ, «что сегодня») не запоминают вообще — тянут
ресерчем на месте (шаг 1). В память идёт только стабильное. Дальше — матрица:

| Данные | Куда | Почему |
|---|---|---|
| Живое: цены, версии, «сегодня» | никуда → ресерч на месте | память устареет и соврёт |
| Правила, роль, стиль | LLM Wiki / файл инструкций | прозрачно, под контролем, читается на старте |
| История чатов, логи | FTS5 | recall по ключевым словам за секунды, дёшево |
| Большие доки, книги, политика | вектор (RAG) | семантика плюс точное цитирование |
| Факты о человеке и проектах | Curator (выжимка) | курируется, а не свалка |
| Рабочее состояние сессии | контекст / кэш | эфемерно: переживает шаг, но не сессию |
| Свои инструкции агента | GEPA / ручная рефлексия | эволюционируют под задачи |

Правило: не тащи вектор туда, где хватит FTS5, и не держи в памяти то, что меняется каждый
день. Разбор вектора (статичный RAG vs динамический/agentic RAG, реальная цена по ОЗУ, чем держать актуальным)
— в знании `agent-memory`, шаг 2.

## Три шага

1. **Свежесть vs хранение** (`agent-internet`). Источник актуального — ресерч. Что не надо
   помнить: живые данные тянешь на месте, а не морозишь в базе.
2. **Лестница и матрица** (`agent-memory`). Полная лестница (вики → FTS5 → RAG →
   Holographic → Curator → GEPA), разбор вектора и правило «тип данных → вид памяти».
3. **Эфемерная память** (`hooks`). Контекст и кэш — краткосрочная RAM агента. Что переживает
   компакт, а что надо вынести наружу, чтобы не потерять.

## Дополнительно

Не шаг маршрута, но практический инструмент нижних ступеней:
- `obsidian-dataweave` — многоцелевой тулкит: начинался как пульт NotebookLM, делает ресерч и
  атомизацию, а для памяти даёт два слоя — **LLM Wiki** (скомпилированная вики) и
  **FTS5-память** (полнотекстовый индекс всего vault). Один из вариантов для ступеней 1–2, не
  единственный и не только про память.

## Как идти по маршруту

Дёрни `next_step("memory-management:1")` — материалы первого шага, дальше по `next_step_id`. На
каждом шаге подбирай под человека и под РЕАЛЬНЫЕ данные (приватность? дешёвый VPS? нужно
цитировать книги? нужна эволюция?), а не по хайпу. Стек памяти — личный, собирается под
конкретного человека.
